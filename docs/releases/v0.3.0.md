## What's new

**Master dependencies.** Tell Syncer that one master needs another one next to it
wherever it's synced. In the rule editor, select a master and click
**Dependencies for selected master…**. A dependency applies to every rule that uses that
master. When a rule has a master but not one of its dependencies, the review tree
flags it under that master. After a check, click **Accept** to add the missing master
to the rule, or tick **Ignore dependencies** to stop being prompted for that rule.

**Name your replicas.** Give a replica a short name instead of seeing its full path
everywhere: select it in the rule editor and click **Name…**. The name belongs to the replica, so every rule that uses it shows the same
name. Hover over it to see the full path.

**See the tree before you check.** Selecting a rule now shows what each replica
should hold, without waiting for a check. Nothing can be synced from this preview.

**Faster first sync of existing replicas.** Files that differ from the master and
have never been synced now read "Differs from master (no sync history)" and can be
resolved in bulk. The conflict dialog gains **Overwrite all remaining from master**
and **Keep all remaining as-is**.

## Improvements

- File masters show as a single file in the review tree instead of a folder that
  holds one file, and the "(dir)"/"(file)" tags are gone.
- Paths in the rule editor, the review tree and `config.toml` now always use Windows
  `\` separators, whether you typed, browsed to or dropped the folder. Existing
  configs are cleaned up the next time you save.

## Fixes

- The rule list is no longer empty on launch when `config.toml` already has rules.
